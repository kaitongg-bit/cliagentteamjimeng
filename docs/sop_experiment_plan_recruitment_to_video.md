# SOP 实验计划：从剧本到招募、分镜、素材、视频生成

## 目标

老板的问题不是“剧本 agent team 是否有效”这一件事，而是：

> 剧本测完后，能否按照 AI 视频生产 SOP，继续验证 agent team 在招募/素材挖掘、分镜、素材生成、视频生成这些节点上是否真的提升产物质量。

本实验计划只围绕《流量寄生虫》继续跑，避免换题导致变量太多。

## 核心假设

1. 剧本阶段的 agent team 价值主要体现在结构、逻辑、主题、可拍性。
2. 招募/素材挖掘阶段的价值不在“盘点完整”，而在“筛出值得花 AIGC 成本生成和锁定的高价值资产”，减少无意义生图和后续一致性返工。
3. 分镜阶段的 agent team 价值主要体现在“把剧本切成可生成的视频 clip，而不是文学分镜”。
4. 视频提示词阶段的 agent team 价值主要体现在“符合工具生成单位、控制屏幕/多人/手部/文字等 AIGC 翻车点”。

## 依赖矩阵

每个节点开始前，Showrunner 必须自检前置依赖是否完成。未完成则倒回补齐，禁止跳步。

| 节点 | 前置依赖 | 不满足时的动作 | 主要交付物 |
|---|---|---|---|
| 1. 创意发散 | Human 输入 | 请 Human 补 brief | 概念方向、故事种子 |
| 2. 剧本 | 创意方向或用户已有梗概 | 先补 10 分钟剧情结构 | 剧本/剧情梗概/场次版 |
| 3. 招募/素材挖掘 | 剧本完成，或用户上传素材 | 从剧本筛出高价值可复用资产 | 人物/空间/道具资产短表、Human 找图任务 |
| 4. 分镜表 | 剧本完成 | 先补 script chunk | 上游 6 列分镜表 |
| 5. 素材生成 | 素材挖掘 + 素材引用 | 先补 moodboard / 引用表 | 人物白底设定、场景图、关键道具图 |
| 6. 视频生成 | AI 脚本 + 素材确认 | 两者缺一不可，缺则倒回 | clip 表、即梦/Seedance 视频提示词 |
| 7. 剪辑成片 | 视频生成完成 | 不在本轮实验内 | 粗剪版本、问题清单 |

注：截图里“招募”这里按“素材挖掘/ casting breakdown”理解，不是招真人演员，也不是完整场务清单，而是从剧本中筛出值得单独生成、锁定和复用的 AIGC 资产。

## 最小角色配置

为避免 agent 太多烧 token，每个节点最多启用 2-3 个子 agent，加一个 Showrunner。

关键原则：每个 SOP 节点都沿用剧本阶段已经验证过的结构：

> 一个主 agent 负责干活产出第一版；少量 reviewer agent 负责提建议、批评、查漏；Showrunner 决定吸收哪些意见并收敛成最终产物。

不要把多个 agent 都安排成并列产出者，否则很容易变成多份结果堆叠，而不是协作提质。

### 固定角色

| 角色 | 何时使用 | 责任 |
|---|---|---|
| Showrunner | 全程 | 自检依赖、决定是否进入下一节点、合并冲突意见 |
| Human | 每个关键准入点 | 选择方向、确认素材、判断审美是否对 |

### 节点角色

| 节点 | 子 agent | 为什么需要 |
|---|---|---|
| 招募/素材挖掘 | 主：素材招募 agent；必要时审：提示词可执行 reviewer、导演/分镜 reviewer | 主 agent 先出短表；提示词 reviewer 检查能否直接喂给即梦和下游提示词；导演 reviewer 检查功能人物、场景可信度和镜头成立性 |
| 分镜表 | 主：导演/分镜 agent；审：观众想象 reviewer、剪辑/声音 reviewer | 主 agent 切 10-15 秒 clip；观众 agent 代替 Human 逐步想象画面，查“看不看得懂/脑中是否能成片” |
| 素材生成 | 主1：美术概念 agent 产出视觉圣经；主2：提示词 agent 产出即梦图片提示词；审：Human + 导演 reviewer | 美术先定视觉圣经，提示词再转成能出好图的即梦提示词，Human 和导演看生成结果是否成立 |
| 视频生成 | 主：提示词结构 agent；审：Human | 视频结果主要由 Human 审，避免 agent 反复看视频消耗大量 token |
| 对照组 | 按节点选择 | 剧本节点适合 single agent baseline；素材挖掘节点优先比较 v1 和 reviewer/Showrunner 后的 v2 |

暂不启用：反方编剧、审片人。  
原因：这轮重点不是重新评剧本，而是测试生产 SOP。观众 agent 在分镜阶段启用，但职责不是评价故事价值，而是代替 Human 做逐步想象和可理解性检查。

## 实验设计

### 实验 A：招募/素材挖掘节点

范围：基于《流量寄生虫》已完成的 `0:00-6:00` 剧本/提示词产物。

输入：

- `traffic_parasite_revised_outline_v1.md`
- `first3min_jimeng_video_prompts_v4.md`
- `second3min_jimeng_video_prompts_v2.md`

实验流程：

1. 素材招募 agent 作为主干活 agent，从剧本和前 6 分钟提示词里输出第一版“素材资产短表”：
   - P0 只保留 5-8 个必须先生成或锁定的资产；
   - P1 只保留 3-6 个可选补充资产；
   - 每个资产必须写明“为什么值得生成/锁定”；
   - 人物资产必须细化外貌、发型、轮廓、服装、核心配饰、表情/动作锚点；
   - 一次性道具、普通群演、背景装饰、不会反复出现的场景不列入素材表；
   - 屏幕文字、logo、合同正文、热搜榜默认交给后期，不要求 AI 生图。
2. Showrunner 先判断 v1 是否已经合格：如果它足够短、准、可执行，可以记录“无需 reviewer”，直接进入素材生成小样。
3. 只有在 v1 仍然过长、漏掉功能人物、或资产不足以支持即梦和下游提示词时，启动提示词可执行 reviewer。它不重写表格，只批评第一版：
   - 哪些人物、功能人群、屏幕元素虽然出现少，但会影响世界成立；
   - 哪些内容必须保留为功能资产，哪些只应进入镜头提示词；
   - 哪些人物、场景、物品描述还不够支持即梦稳定生成。
4. 只有在 v1 仍然不足以支撑镜头调度和场面可信度时，启动导演/分镜 reviewer。它不重写表格，只批评第一版：
   - 哪些一次性功能人物不能删；
   - 哪些镜头需要的关系资产、位置资产或场面人群还没进表；
   - 哪些内容其实属于分镜/调度，不应升级为独立生成资产。
5. Showrunner 合并为 v2：
   - 吸收 reviewer 意见；
   - 删除低价值项；
   - 标注哪些是必备素材、可选素材、禁止生成素材；
   - 输出最终“素材资产短表”。

对照方式：

- 本节点不强制做 single agent baseline。
- 主要比较 `v1 主素材 agent` 与 `v2 reviewer/Showrunner 后` 的差异。
- 如果 v1 已经达到短、准、可执行，则结论可以是“该节点不需要 reviewer，单素材 agent 足够”。

交付物：

- `recruitment_material_breakdown_v1_by_recruitment_agent.md`
- `recruitment_reviewer_prompt_structurer.md`
- `recruitment_reviewer_director.md`
- `recruitment_material_breakdown_agent_team.md`
- `recruitment_material_breakdown_v1_vs_v2_comparison.md`

可选历史对照：

- 如果已经有 single agent baseline，可以作为附录保留，但不再作为本节点的主实验方法。

评分维度：

| 维度 | 说明 |
|---|---|
| 完整性 | 是否漏掉关键演员、场地、道具、屏幕类素材 |
| 可复用性 | 是否识别哪些素材跨 clip 复用 |
| 叙事必要性 | 是否区分“必须有”与“只是好看”的素材 |
| 视觉统一性 | 是否能支撑后续视觉圣经和 moodboard |
| 生成风险意识 | 是否标注可读文字、手部、多人、屏幕风险 |
| Human 可用性 | 用户能不能直接照着找参考图/上传素材 |
| 后续依赖价值 | 是否能直接喂给分镜和素材生成节点 |

新增负向评分：

| 维度 | 扣分方式 |
|---|---|
| 文档冗长 | 超过一页、低价值项过多、Human 看完仍不知道先做什么 |
| 生成成本浪费 | 把一次性道具、普通背景、可在提示词里顺手描述的东西列成独立素材 |
| 人物不够具体 | 人物只写身份，不写外貌、服装、轮廓、发型和动作锚点 |

### 实验 B：下一个 3 分钟片段

范围：`6:00-9:00`。  
目标：继续推进“黑料开始外化，但不做全网骂声快剪”，测试 agent team 在下一片段的稳定性。

推荐剧情方向：

- 沈砚被带离庆功宴；
- 公司车/地下停车场/酒店后门；
- 他第一次看到被剪裁的监控、录音、聊天截图碎片；
- 张总要求他发低姿态回应；
- 他拒绝，但手机和账号已不在自己手里；
- 片尾钩子：品牌/平台/媒体电话陆续进来，但还不进入第二天全网崩塌。

启用角色：

1. 主：编剧/连续性 agent，只定 `6:00-9:00` beat，确保不跳到后面剧情。
2. 审：导演/分镜 reviewer，批评 beat 是否可拍、空间是否连贯。
3. 主：导演/分镜 agent，基于 Showrunner 通过的 beat 输出 12 个 15 秒分镜段落。
4. 审：观众想象 reviewer，逐条复述自己脑中看到的画面，指出看不懂、空间断裂、情绪跳跃的地方。该 reviewer 用来替代 Human 的“凭空想象”能力。
5. 审：剪辑/声音 reviewer，检查节奏、声音桥、转场和可剪辑性。
6. 主：提示词结构 agent，把通过审核的分镜压成即梦视频提示词。
7. 审：生成风险 reviewer，检查屏幕、手、多人、可读文字等失败点。

交付物：

- `third3min_showrunner_synthesis_v1.md`
- `third3min_jimeng_video_prompts_v1.md`
- `third3min_prompt_review.md`
- `third3min_jimeng_video_prompts_v2.md`

对照组：

- `third3min_single_agent_baseline.md`

评分重点：

- 是否继续保持“流程恐怖”，而不是变成热搜狗血。
- 是否和 0:00-6:00 的人物、空间、手机/账号接管连续。
- 观众 agent 是否能逐条想象出画面；如果观众 agent 复述不出来，说明分镜还不够清楚。
- 是否每条提示词都能直接给即梦生成。
- 是否减少可读文字、屏幕、手部、多人群像的失败概率。

### 实验 C：素材生成小样

范围：不全量生成，只做最小可验证素材包。

选择 5 个高价值素材：

1. 沈砚人物三视图/白底设定。
2. 张总人物三视图/白底设定。
3. 高层酒店庆功宴空间参考。
4. 冷白服务通道空间参考。
5. 临时公关房间空间参考。

启用角色：

1. 主：美术概念 agent，先输出视觉圣经：
   - 人物外貌/服装/年龄质感；
   - 场景材质和空间真实感；
   - 光线、镜头、影调；
   - 可参考的电影/纪录片/摄影方向；
   - 明确禁止的风格，如短剧豪华、AI 精致假、综艺棚拍。
2. 主：提示词 agent，基于视觉圣经输出即梦图片提示词：
   - 人物白底三视图提示词；
   - 场景参考图提示词；
   - 道具参考图提示词；
   - 每条都短、结构清楚、减少可读文字和复杂手部。
3. 审：Human，看生成结果是否符合心中质感。
4. 审：导演 reviewer，看生成图是否能支撑后续分镜和镜头调度。

交付物：

- `visual_bible_v1_by_visual_concept_agent.md`
- `visual_asset_prompt_pack_v1.md`
- 即梦生成图或外部参考图索引
- `visual_asset_director_review.md`
- `asset_confirmation_report.md`

评分重点：

- 人物是否能跨 clip 保持一致；
- 场景是否符合电影级真实感；
- 是否避免“AI 精致假”“短剧豪华”“屏幕文字错误”；
- Human 是否能明确说出要/不要。
- 导演是否确认这些素材能服务后续镜头，而不是只作为漂亮概念图。

### 实验 D：视频生成小样

范围：只取 5 条推荐 clip 试生成，不全量 9 分钟。

从当前 `3:00-6:00` v2 先选：

1. `01 3:00-3:15`：庆功仍在、手机已离身。
2. `07 4:30-4:45`：服务通道真实感。
3. `08 4:45-5:00`：权限交接是否翻车。
4. `10 5:15-5:30`：手机够不到的权力关系。
5. `12 5:45-6:00`：冷白房间与暖金庆功宴对照。

启用角色：

1. 主：提示词结构 agent，根据实际生成结果改 prompt。
2. 审：Human，判断视频是否成立。这里暂不默认让 agent 看视频，因为视频理解和逐帧审查会消耗大量 token。
3. 可选：生成风险 reviewer。只有当 Human 无法判断失败原因时才启用，负责区分是模型能力、素材不足，还是提示词问题。

交付物：

- 每条 clip 的提示词、素材引用、生成结果路径。
- `video_generation_test_report.md`
- `prompt_revision_notes.md`

评分重点：

| 维度 | 说明 |
|---|---|
| 画面真实感 | 是否像电影，而非短剧/广告/综艺 |
| 动作可读性 | 观众是否能看懂“手机离身/权限交接/解释权丢失” |
| 生成稳定性 | 人脸、手、屏幕、文字是否崩 |
| 连续性 | 沈砚、张总、空间、光线是否延续 |
| 可剪辑性 | 15 秒内部是否有起承转合 |

## 每轮实验固定输出格式

每个实验节点都按同样结构输出，方便老板横向看：

```text
01_input/
  输入文件和用户确认

02_agent_team/
  子 agent 原始产物
  showrunner synthesis
  final deliverable

03_baseline_or_v1/
  剧本节点放 single agent baseline
  素材挖掘节点放主素材 agent v1

04_comparison/
  评分表
  剧本节点比较 agent team vs single agent
  素材挖掘节点比较 v1 vs v2
  成本/时间/token 备注

05_next_action/
  是否进入下一节点
  如果不进入，缺哪个依赖
```

## 成功标准

不是“agent team 每次都赢”，而是要能回答：

1. 哪些节点 single agent 足够好，可以不用 agent team？
2. 哪些节点必须引入少量角色才能显著减少返工？
3. 哪些角色最有性价比？
4. Human 应该在哪些准入点介入？
5. 哪些产物可以产品化成固定入口？

初步预期：

- 剧本：编剧 + 反方/观众/导演价值高。
- 招募/素材挖掘：先看素材招募主 agent 是否能独立产出短、准、可执行的资产表；reviewer 只在 v1 无法支撑即梦生成、功能人物遗漏、镜头世界不成立时启用。
- 分镜表：导演/分镜主 agent + 观众想象 reviewer + 剪辑/声音 reviewer 价值高。
- 素材生成：美术概念主 agent + 提示词主 agent + Human/导演 review 价值高。
- 视频生成：提示词主 agent + Human review 为主；生成风险 reviewer 只在定位失败原因时启用。
- 全程不建议堆很多 agent，Showrunner 必须负责收敛。

## 下一步建议

立刻执行实验 A：招募/素材挖掘。

原因：

1. 截图 SOP 明确要求剧本完成后启动招募/素材挖掘。
2. 我们已经有 `0:00-6:00` 的剧本化视频提示词，足够筛出高价值人物、空间、道具资产。
3. 这个节点能直接检验“主素材 agent v1 是否足够”，以及 reviewer 是否真的能把 v1 压短、压准、减少后续生图成本。

实验 A 完成后，再进入实验 B：`6:00-9:00` 下一片段。
